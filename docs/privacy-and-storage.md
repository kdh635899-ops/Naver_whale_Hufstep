# 개인정보·저장·권한

## 저장 위치와 방식

- 확장앱 origin의 **IndexedDB**(`hufstep` DB, `kv` 스토어)에만 저장합니다. 서버·클라우드·동기화 없음. 같은 PC의 같은 웨일 프로필에만 남습니다.
- 키 구성
  - `appState`: 학생 조건, 과목, 성적 스냅샷 **메타데이터**(합계·경고·과목 ID), 평가일정, 과목별 자유 메모·수업 시간(요일·시각), 제출 완료 표시, 예상 성적 시나리오, 인증 학생확인, 알림 설정, 동의 기록(버전·시각). 사이드바만 씁니다.
  - `notifLog`: 알림 발송 이력 키(`종류:날짜:학기`). 서비스 워커만 씁니다.
  - `pendingRoute`: 알림 클릭 시 열 날짜.
- 붙여넣은 **원문 전체는 저장하지 않습니다.** 분석은 Web Worker에서 하고, `확인하고 반영` 후 입력란을 비웁니다. 확인 전에는 아무것도 저장하지 않습니다.
- 저장 전 zod 스키마 검사를 통과해야 하며, 실패하면 기존 정상 데이터를 그대로 둡니다. 여러 항목은 한 트랜잭션으로 저장합니다.
- `schemaVersion` + migration 단계. 읽기에 실패하거나 더 새 버전의 데이터면 **덮어쓰지 않고** 오류 화면을 보여 줍니다.
- 받지 않는 정보: 이름, 전체 학번(입학 연도만), 생년월일, 연락처, 학교 비밀번호·쿠키.

## 보호 범위와 한계

- 보호 수단은 브라우저 origin 분리와 기기 접근 통제뿐입니다. **저장 데이터는 암호화되어 있지 않습니다.** 같은 PC·같은 웨일 프로필을 쓰는 사람은 볼 수 있습니다.
- 암호 vault는 구현하지 않았습니다 (명세 §9.1: 필수 아님).

## 권한

| 권한 | 이유 |
| --- | --- |
| `alarms` | 서비스 워커에서 전날·당일 알림 예약 |
| `notifications` | 시스템 알림 표시 |

없음: `host_permissions`, `content_scripts`, `tabs`, `scripting`, `cookies`, `clipboardRead`, `storage`(IndexedDB만 사용), `externally_connectable`, `action`.
CSP: `script-src 'self'` 등 원격 스크립트·`eval` 금지. 스크립트·스타일·아이콘은 모두 패키지에 포함, 폰트는 시스템 글꼴.
종정시 링크는 학생이 눌러 새 탭으로 여는 일반 링크(`noopener noreferrer`)이며, 학교 화면을 읽거나 로그인하지 않습니다.

## 동의

- **학업정보 처리 동의**: 붙여넣기 분석·과목 추가·평가 수정 전에 목적·항목·저장 위치·전송 안 함·보관/삭제·한계·거부 시 영향을 보여 주고 받습니다. 동의 없이도 데모 둘러보기와 조건 기반 요건 안내는 볼 수 있습니다.
- **알림 동의**: 마이페이지에서 별도로 받습니다. 알림을 꺼도 모든 핵심 기능은 동작합니다.

## 삭제

| 동작 | 지우는 것 | 남는 것 |
| --- | --- | --- |
| 과목 삭제 | 그 과목 + 연결된 평가일정·완료 표시·자유 메모·수업 시간·시나리오 항목 | 나머지 |
| 학업정보 삭제 | 과목, 성적 스냅샷, 평가일정, 완료 표시, 자유 메모, 수업 시간, 시나리오, 인증 확인 | 학생 조건, 설정, 동의 기록 |
| 학업정보 동의 철회 | 위 + 동의 기록, 알림 끔 | 학생 조건 |
| 전체 초기화 | IndexedDB의 모든 키 + 서비스 워커가 우리 알람·표시 중 알림·발송 이력 정리 | 없음 |

학업정보가 지워지면 서비스 워커가 저장 상태를 다시 읽어 남은 예약을 정리합니다.

## 알림

- `whale.alarms`로 서비스 워커에서 예약하고 `whale.notifications`로 표시합니다 (사이드바의 setTimeout 아님).
- 날짜별로 한 번, 문구는 **건수만** (`내일 시험 2개 · 제출 1개`). 과목명·성적은 넣지 않습니다.
- 당일 알림 시각 = min(설정 시각, 첫 시간 있는 일정 30분 전). 이미 지났으면 남은 일정이 있을 때만 1분 뒤 한 번.
- 설치·시작·1시간 주기 점검·알람 실행·사이드바 저장 때마다 저장 일정과 실제 예약을 비교해 복구/정리합니다. 알람이 울리면 최신 설정·동의·일정을 다시 읽어 판단하므로 설정 변경 직전의 예약이나 동의 철회 후의 예약은 표시되지 않습니다.
- 브라우저·PC가 꺼져 있거나 OS가 알림을 막으면 알림을 보장하지 않으며, 복귀 후 지난 알림을 몰아서 보내지 않습니다.
- 가상 데이터 모드에서는 알림을 예약하지 않습니다.
